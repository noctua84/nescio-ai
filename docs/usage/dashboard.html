The cause — context compounds with every turn

Context grows about 2.4k tokens per request and never shrinks. A session opens at 84k and crosses the 200k line around request 55. Every request re-sends the whole accumulation, so the shaded band is not a rate — it is volume paid for again on every single turn.

Median context by request position, pooled across all 169 sessions. Truncated at request 279; beyond that the sample thins and the tail distorts.

Daily burn

Roughly a threefold step change on 13 August — from 300–700 requests a day to 1,400–2,000. The 14th alone cost 110M weighted tokens, more than all of 12–23 July combined.

The levers, ranked by what they return

1

Cap or clear context near 200k

31–43%est. savinghigh confidence

49% of every context token you have ever sent — 3,566M of 7,245M — is the portion sitting above the 200k mark. 66% of all requests carry more than 200k. This is not a tuning knob; it is half the bill.

Drop opus[1m] to a 200k model, or /clear on task boundaries instead of running one long session.

2

Break up marathon sessions

up to 17%est. savinghigh confidence

Your two largest sessions — 1,300 and 1,198 requests — together burned 195M weighted tokens: 17% of six weeks of spend, from two sittings. Median session is 78 requests; p90 is 284.

A session past roughly 80 requests is carrying far more history than it is using.

3

Trim the session preamble

≈6%est. savingmedium confidence

Every session opens at 72k tokens before you type — MCP tool schemas, 7 plugins, the skills listing, and a 12.8k-character orchestrator prompt. That floor is re-sent on all 20,903 requests: 1,505M tokens, 21% of all context.

Halving the preamble to ~36k returns roughly 6% of weighted spend. Disable MCP servers you are not using in a given project.

4

Tier the model

unquantifiedest. savingmedium confidence

100% of spend is Opus — 80% opus-4-8, 19% opus-5. Bash alone is 12,921 of ~16,700 tool calls, and mechanical shell work does not need the frontier model. The crew has since moved to claude-opus-5, which is priced identically to 4.8 — so that was a free upgrade, not a saving.

The lever is the main loop, not the subagents. Route routine sessions to Sonnet.

5

Reconsider always-high effort

≈2% directest. savinglow confidence

Every one of 18,432 recorded requests ran at effort: high. Thinking is 4.87M of 29.53M output tokens.

Direct cost is small. The indirect cost — longer outputs, more tool loops — is real but not measurable from this data.

What this cannot tell you

Subagent spend is unmeasured

1,842 Agent calls appear in the transcripts and not one records its internal token count. At a plausible 20–50k each that is 37–92M tokens, 0.5–1.3% of the total — an estimate, not a measurement. It is the one number here that could not be verified.

The weighting is published, the accounting is not

Since this page was first built, the multipliers have been checked against Anthropic's own pricing rather than inferred: Opus is $5.00/1M in and $25.00/1M out (the ×5), with cache writes at ≈×1.25 and cache reads at ≈×0.1. What remains undocumented is whether subscription weekly limits use the same accounting as API billing. If they count raw tokens, cache reads are 96.7% of everything and lever 1 gets bigger, not smaller.

The source format is unofficial

These figures are parsed from session .jsonl files that Anthropic documents as internal and version-unstable. The numbers are right today; the parser can break on any release.
