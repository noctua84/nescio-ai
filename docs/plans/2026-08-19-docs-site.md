### Key structural decisions this plan makes (derived from the constraints)

1. **Two isolated top-level dirs, both off the allowlist:** `brand/` (generators,
   `palette.py`, static assets, fonts) and `docs_site/` (`mkdocs.yml`, content,
   theme overrides, CSS, catalog generator). This makes the isolation boundary one
   sentence: *neither `brand/` nor `docs_site/` is on `FRAMEWORK_PATHS`.*
2. **Tests that import `brand/` or `docs_site/` must NOT live in `tests/`.**
   `tests/` is on `FRAMEWORK_PATHS`, so it is copied into derived instances — which
   do **not** receive `brand/` or `docs_site/`. A `tests/test_*.py` importing
   either would crash the instance's `python -m unittest`. Therefore brand/site
   tests are **co-located** (`brand/test_*.py`, `docs_site/test_*.py`) and run by
   the **docs workflow**, not `tests.yml`. The one allowed exception is the
   isolation guard test (Task 13): it imports only `sync_from_upstream` and asserts
   a constant, so it may live in `tests/`.
3. **Split pure-Python generation from rasterisation.** `palette.py`,
   `make_brand.py` (SVG), `make_diagrams.py` (SVG + twins), and the catalog
   generator are stdlib-only and CI-runnable. `render_diagrams.py` +
   `make_favicons.py` (Chromium/Pillow) are **local-only, human-run**; their
   outputs (favicon binaries) are committed.
4. **Retire the irreversible risk first (Rev 2).** The only effectively
   irreversible step is the first public deploy. It is scheduled as WAVE 0 against
   a trivial stock-theme page, so DNS, cert provisioning, Pages-from-Actions, the
   fork guard, and scrub-on-output are all proven before any brand work — after
   which later waves pour content into a pipeline already known to work.
5. **The Plex migration is off the critical path (Rev 2).** The site launches on
   the self-hosted **current** faces; migrating to IBM Plex is the last wave and
   does not gate launch.

## Verification Strategy

- **Deploy pipeline (WAVE 0):** the stock-theme thin slice serves a real page over
  HTTPS on the canonical repo; the workflow is green; a fork's Actions is skipped
  by the `if:` guard; `scrub_check.py` runs against the built `_site`.
- **Palette / drift:** a co-located test asserts every generator's colour
  constants resolve through `palette.py` and no retired hex (`#8a919b`, `#111418`)
  appears in any generator source or generated SVG.
- **WCAG:** compute the WCAG 2.1 contrast ratio for `muted` on white in a test
  (assert ≥ 4.5); re-verify all pairs in spec §2 with an external checker before
  launch (human).
- **Tokenised SVG:** test asserts generated diagram source contains no `<rect
  ... fill="#…">` ground and no literal hex fills — only `var(--…)`; twins contain
  concrete hexes and no `var(`.
- **Catalog (dynamic guard):** test feeds fixture frontmatter and asserts every
  agent/skill row renders with name+description; a build-time assert fails if the
  **rendered catalog count diverges from the live `agents/` + `skills/` directory
  listing** (catches a silently dropped file without punishing an addition).
- **Site build:** `mkdocs build --strict` succeeds (fails on broken links/nav);
  `scrub_check.py` on the built output exits 0.
- **Isolation:** guard test asserts `brand`, `docs_site`, `mkdocs.yml`, `docs`
  are absent from `FRAMEWORK_PATHS`.
- **Existing CI:** `tests.yml`, `scrub.yml`, `release-please.yml` stay green
  (they never see `brand/`/`docs_site/` tests).
- **Visual (human):** diagrams in both schemes, wordmark rendering, font
  legibility — see the human callouts per task.
- **Plex migration (T16, off critical path):** verified separately after launch —
  no diagram text overflows its box in either scheme, legibility at body + caption,
  wordmark re-outlined from Plex Mono, social card re-checked.

```
Wave 0  Thin vertical slice     T1 stock Material + placeholder + FULL deploy workflow (fork-guarded, scrub-on-output) → real page over HTTPS

Wave 3  Site                    T8 mkdocs+schemes+Material pin │ T9 css │ T10 catalog (dynamic guard) │ T11 pages (T11 needs T4,T7,T8,T9,T10)
Wave 4  Deploy finalize+guards  T12 enrich workflow (catalog+tests) │ T13 isolation guard │ T14 derivation │ T15 readme
```

T13, T14, T15 run alongside it. **T16 (Plex) is explicitly off the critical path —
the site is launch-complete without it.** The three isolation cleanups (T13–T15)
depend on nothing and can start immediately, but land cleanest after
`brand/`+`docs_site/` exist.

## Reversibility summary

- **Reversible (git):** every task's file changes — thin slice, palette,
  generators, fonts, site, workflow, README, Plex migration.
- **Effectively irreversible:** the **first successful public deploy** (crawlers
  and caches capture it) — now the **WAVE 0 thin slice (T1)**, deliberately
  scheduled first so the risk is retired against a trivial stock page while the
  `if:` fork guard and the scrub-on-output step are confirmed. Later content ships
  into a pipeline already proven public.
- **External toggle:** "Enforce HTTPS" (reversible, but cert provisioning lags up
  to 24h) — handled at the T1 first deploy. DNS, Pages-source, domain, and
  verification are already done — nothing to change there.
- **Human filesystem move:** the Drive archive relocation in T3 is reversible by
  the owner; keeping only the repo copy live is the point (prevents drift).
