The rule that must not bend. Periwinkle carries dark mode, brand blue carries light. #8fb0d9 on white is 2.2:1 — it may be a fill or a border, never text or a link.

03 · Type

What ships today

Plex Sans and Plex Mono share skeletons and metrics, so mono identifiers sit beside sans prose as siblings. Liberation Mono + Carlito came from unrelated families and read that way.

Nescio Mono · identifiers nescio orchestrator · critic · memory/ Agent names, commands, filenames, tokens. Anything that is a literal in the system.
Nescio Sans · prose Aa One orchestrator, nine specialists. Delegation goes down; every result comes back through the gate. Headings, running text, captions, UI labels.

The split is semantic, not decorative. Mono means "this is a thing you can type." Readers absorb the rule in one page and never have to be told it.

This page embeds the real subset woff2 files, so the type above is exactly what the site serves — no fallback. The faces are Liberation Mono and Carlito, renamed to Nescio Mono / Nescio Sans because SIL OFL clause 3 forbids a Reserved Font Name on a modified subset. IBM Plex remains the wave 5 target.

07 · Diagrams

One source, both schemes

The confirmed pipeline: a single tokenised SVG with no background rect and no hardcoded fills, inlined into the page so the site's variables reach it. Press the button — the SVG below is one element, recoloured by CSS custom properties alone.

Same DOM node. Only the token values change.

Schematic stand-in for diagram-crew.svg. The dashed #a8b0ba node holds its colour in both schemes — that is the planned, not shipped convention doing its job.

What the site gets for free. Inlining means the scheme toggle recolours diagrams instantly, with no second file to keep in sync. The *-light.svg / *-dark.svg pair is generated from this same source for GitHub's README and link previews, which can't supply CSS variables — so the twins can never drift from the original.

08 · Layout

Diagrams do not fit the column

Measured on the built site at a 1440px viewport, not estimated. Material’s three-column layout leaves the article a fraction of the width the artwork needs.

Prose measure is unchanged at 551px throughout — only the diagrams break out. Gutters stay symmetric and no width in the stylesheet references 100vw, so the scrollbar cannot induce a page-level scroll.

The obvious implementation would have been broken, invisibly. The usual full-bleed trick — margin-inline: calc(50% - 50vw) — centres a box on its containing block, and Material’s article column is not viewport-centred. Measured offsets from the viewport centre: −68px at 1440, −213px at 1024. The box would have hung past the left edge, where the artwork is unreachable at scrollLeft: 0. Left overflow never shows up as a page scrollbar, so no automated check would have caught it.

The root cause was not the diagram. width: auto on a child can never exceed its containing block, so while .md-content__inner itself carried the 68ch measure cap, the diagram was pinned to 551px whatever its margins said. The fix moves the cap off the article and onto its blocks — prose stays at 551px, the diagram is free.

Narrow viewports: accepted, not overlooked. Below roughly 800px the break-out buys nothing — there is no viewport left to break into. 1400×826 is a landscape composition and phones are portrait, so this is an aspect-ratio mismatch, not a sizing bug, and no amount of CSS resolves it. These docs skew desktop, and a legible diagram you scroll beats a shrunken one you cannot read.

Two fixes were considered and deliberately declined, recorded so they are not re-filed as bugs: reflowing the SVG responsively under a media query inside the artwork (the real fix, cheap in principle since the generator is programmatic), and raising the diagram type floor from 11.5px to ~14px to tolerate a ~20% downscale.

09 · Build

Generator status

The brand is code, not files — every asset is reproducible, nothing is hand-edited. That is why the palette normalisation will hold instead of drifting again in six months.

GeneratorProducesStatus
make_brand.pyMark, badge, social card, Medium cover, size sheetPRESENT
make_diagrams.pyBoth diagram SVGsPRESENT
make_favicons.pyFull favicon setPRESENT
render_diagrams.py2× PNGs from the diagram SVGsPRESENT

The palette drift is a three-line problem. Each script declares its own constants at the top — make_brand.py has INK #111418, make_diagrams.py has INK #16191f and MUTED #8a919b. One shared palette.py replaces all three. And the WCAG failure is a single line: MUTED = "#8a919b" becomes "#6b727c", and both diagrams pass on the next run.

All scripts are sandbox artefacts. They write to /home/claude/, and both render_diagrams.py and make_favicons.py hardcode a Chromium path under /opt/pw-browsers/ and need Pillow. Making them run locally and in CI is a build task, not a blocker.

The plan

Sixteen tasks, re-ordered after a devil's-advocate pass. The original sequencing put the one irreversible step — the first public deploy — last, behind ten reversible ones. This retires that risk first instead.

What moving the brand into the repo has already caught. Three defects that were invisible while the generators lived on Drive as unreproducible files:

— The favicons were clipped. favicon-512.png had 27 unpainted rows at the bottom and the Apple touch icon 7 — a paint race in the original sandbox render, so the rounded corner was never drawn. Regenerated: zero, with a pixel-identical owl and a regression guard.

— The diagram PNGs rendered pure black. The rasteriser embedded the tokenised SVG in an HTML body, so its svg:root defaults never matched and every fill fell back to SVG’s initial black. 1.7 million black pixels, zero palette colours. Nothing shipped — no PNGs are tracked.

— The font families would not have matched. The OFL forbids a Reserved Font Name on a subset, so the self-hosted faces ship as Nescio Mono / Nescio Sans — while the palette still named the upstream faces. Every diagram would have quietly fallen back to a system font with all tests green.

The thing to watch over 12 months. Not the fonts and not the SVGs — the custom Material scheme. Its CSS-variable names have changed across Material releases, and no test catches a periwinkle that quietly reverts to the stock accent. Pin Material hard, comment the pin, and treat any upgrade as a deliberate task with a visual re-check rather than a routine bump.
