# nescio favicons

Generated by `make_favicons.py` from the same owl geometry as the rest of the
brand assets. Change `make_brand.py`'s `owl()` and re-run both scripts, or these
drift out of sync with the logo.

## Files

| File | Size | Used by |
|---|---|---|
| `favicon.svg` | vector | Modern browsers — scales to any size, one file |
| `favicon.ico` | 16/32/48 | Legacy fallback, and Windows shortcuts |
| `favicon-16.png` | 16×16 | Tabs, bookmarks |
| `favicon-32.png` | 32×32 | Taskbar, high-DPI tabs |
| `favicon-48.png` | 48×48 | Windows site icons |
| `favicon-192.png` | 192×192 | Android home screen, PWA manifest |
| `favicon-512.png` | 512×512 | PWA splash, store listings |
| `apple-touch-icon.png` | 180×180 | iOS home screen |

## Drop into `<head>`

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/favicon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="manifest" href="/site.webmanifest">
```

That order is deliberate: browsers that understand SVG take the SVG, everything
else falls back to the `.ico`. The `sizes="32x32"` on the ICO stops Chrome
downloading it when it has already chosen the SVG.

## `site.webmanifest`

```json
{
  "name": "nescio",
  "short_name": "nescio",
  "icons": [
    { "src": "/favicon-192.png", "type": "image/png", "sizes": "192x192" },
    { "src": "/favicon-512.png", "type": "image/png", "sizes": "512x512" }
  ],
  "theme_color": "#2f4d7a",
  "background_color": "#0e1319",
  "display": "standalone"
}
```

## Design notes

**Tile, not bare mark.** These use the badge form — white owl on an accent tile
— rather than the transparent mark. A tab bar can be light or dark depending on
theme, and a dark-blue silhouette on transparency vanishes against dark chrome.
The tile carries its own background, so it reads either way.

**Apple touch icon has square corners.** iOS applies its own rounded mask; if the
source is already rounded you get a double-rounded corner. The mark is also
scaled slightly smaller there so nothing important sits near the clipped edge.

**Rasterised once at 512, then downscaled.** Rendering a 16×16 headless browser
window races the paint and produces half-drawn frames. A Lanczos downscale from
512 is both reliable and sharper.

**No simplified 16px variant.** One was tried — beak removed, eyes enlarged — and
at 16×16 it was indistinguishable from the standard geometry. Not worth
maintaining a second shape for no visible gain.
